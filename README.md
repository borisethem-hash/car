# 車両管理システム

約100台・8事業部の車両について、**車両台帳・車検期限・修理/整備履歴・修理費用**をまとめて管理するWebシステムです。

---

## 1. まず動かしてみる（デモ）

### 必要なもの
- **Node.js**（バージョン 20 以上）… https://nodejs.org/ja から「LTS」をインストール

### 手順
このフォルダでコマンドプロンプト（または PowerShell）を開き、次を順番に実行します。

```bash
npm install        # 初回のみ：必要な部品をダウンロード
npm run build      # 本番用に組み立て
npm start          # システムを起動
```

ブラウザで **http://localhost:3000** を開くとログイン画面が表示されます。

### テスト用アカウント（ログイン画面にも表示されています）

| 種類 | メールアドレス | パスワード | できること |
|---|---|---|---|
| 管理者 | admin@example.com | admin1234 | すべての機能 |
| 一般ユーザー | user@example.com | user1234 | 東京事業部の車両の閲覧・修理登録 |

> 初回アクセス時に、デモデータ（車両100台・修理履歴 約740件・業者8社・利用者6名）が自動で作られます。

## 3. 技術構成（ご提案内容）

| 項目 | 採用技術 | 選んだ理由 |
|---|---|---|
| 開発言語・フレームワーク | **Next.js（TypeScript）** | 画面と処理を1つにまとめられ、保守する会社・技術者が見つけやすい |
| データ保存 | 社内PC：**JSONファイル**（`data/db.json`）／ Vercel：**メモリ（デモ）**、Redis 接続時は **Upstash Redis** | 環境に合わせて自動で切り替え。Vercel は設定不要でそのまま動作 |
| ログイン | 暗号化パスワード＋署名付きCookie | 外部サービス不要。パスワードは元に戻せない形で保存 |
| 画面デザイン | Tailwind CSS | シンプルで見やすく、スマートフォンにも対応 |

**100台・利用者数十名の規模であれば、この構成で十分に運用できます。**
将来、利用者が大幅に増える・複数拠点のサーバーで動かす場合は、データ保存先を PostgreSQL などのデータベースに切り替えられるよう、データの読み書きは `lib/db.ts` の1か所にまとめています。

## 4. 本番運用を始めるとき

### ① 秘密の鍵を設定する（必須）
フォルダ直下に `.env.local` というファイルを作り、次の1行を書きます（右側は推測されにくい長い文字列に変えてください）。

```
SESSION_SECRET=ここに40文字以上のランダムな英数字
```

HTTPS（`https://`）で公開する場合は、次の行も追加します。

```
COOKIE_SECURE=true
```

### ② デモデータを消して、実データで始める
1. 管理者でログインし「マスタ管理」で事業部・車両区分・業者を実際の内容に直す
2. 「利用者管理」で社員のアカウントを作成し、**テスト用アカウントは削除または利用停止**にする
3. デモの車両・履歴を削除してから実際の車両を登録する

> ※ログイン画面のテスト用アカウント表示は `app/login/LoginForm.tsx` の `testAccounts` を空にすると消えます。

### ③ サーバーの選び方（おすすめ順）
1. **Vercel ＋ Upstash Redis** … サーバー管理が不要。小規模なら無料枠で運用可能（手順は下記）
2. **社内のWindowsパソコン/サーバー**で `npm start` … 社内ネットワークだけで使う場合に手軽
3. **VPS（さくらのVPS、ConoHa など）** … 社外からも使う場合。月額1,000円前後から

### ④ Vercel で公開する場合

**設定は不要です。** GitHub のリポジトリを Vercel にインポートするだけで、そのまま動きます。

Vercel 上では自動的に **デモモード** になります。

- データベースもファイルも使わず、サーバーのメモリ上でデモデータ（車両100台など）を動かします
- ログイン・検索・登録・編集・削除・集計・CSV出力など、**すべての機能を試せます**
- 登録・変更した内容は、しばらくアクセスがないと初期のデモデータに戻ります（画面上部とログイン画面に表示されます）
- 社内のPCで `npm start` した場合は、これまで通り `data/db.json` に保存されます
- どの環境でも、環境変数 `DEMO_MODE=true` を設定するとデモモードになります

#### 本番運用でデータを残したい場合（任意）
1. Vercel のプロジェクト画面 → **Storage** → **Create Database** → **Upstash for Redis**（無料枠あり）を作成
2. このプロジェクトに **Connect**（環境変数 `KV_REST_API_URL` と `KV_REST_API_TOKEN` が自動で設定されます）
3. **Settings → Environment Variables** に `SESSION_SECRET`（長いランダムな文字列）を追加
4. **Deployments** から最新のデプロイを **Redeploy**

> Redis を接続すると自動的に本番モードに切り替わり、デモ版の表示も消えます。バックアップは Upstash の管理画面からエクスポートしてください。

## 5. 日々の維持管理

| 作業 | 頻度 | 方法 |
|---|---|---|
| **バックアップ** | 毎日〜毎週 | `data/db.json` を別の場所（NAS・クラウドストレージ等）にコピー |
| 復元 | 必要時 | システムを停止 → バックアップの `db.json` を `data` フォルダに戻す → 起動 |
| 利用者の追加・退職者の停止 | 随時 | 管理者が「利用者管理」から操作 |
| パスワード忘れ | 随時 | 管理者が「利用者管理」で新しいパスワードを設定 |
| 部品の更新 | 半年〜1年 | `npm update` → `npm run build` → 再起動（事前にバックアップ） |

### デモデータに戻したいとき
- 画面から：管理者で「マスタ管理」→「デモデータに戻す」
- コマンドから：`npm run reset-data`（次回アクセス時にデモデータが再作成されます）

## 6. フォルダ構成（技術者向け）

```
app/            画面（ページ）
  login/        ログイン画面
  (main)/       ログイン後の画面（ホーム・車両・修理・集計・マスタ・利用者・ガイド）
  api/export/   CSV出力
components/     画面部品（フォーム・ボタン・メニューなど）
lib/
  actions.ts    登録・更新・削除の処理（権限チェックを含む）
  auth.ts       ログイン・権限
  db.ts         データの読み書き
  seed.ts       デモデータの作成
  queries.ts    検索・絞り込み
data/db.json    データ本体（自動作成。バックアップ対象）
```

### よく使うコマンド
| コマンド | 内容 |
|---|---|
| `npm run dev` | 開発用に起動（変更が即時反映） |
| `npm run build` | 本番用に組み立て |
| `npm start` | 本番用に起動（ポート変更：`npm start -- -p 8080`） |
| `npm run reset-data` | データをデモの初期状態に戻す |
